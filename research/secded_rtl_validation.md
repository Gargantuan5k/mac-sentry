# Initial SECDED RTL validation — 2026-10-14

Separate `secded_encoder`, `secded_decoder`, and `mac_secded` modules implement
the [SECDED contract](../spec/secded_accumulator.md). The unprotected core remains
the reference variant. These results concern RTL simulation and generic synthesis.

## Reproduction

```sh
make test-secded-rtl
make test-secded-small
make lint-secded synth-secded
make lint-secded synth-secded OPERAND_WIDTH=4 ACC_WIDTH=8
make test-model
```

The Makefile default seed is 20260923. `make all` now includes both MAC variants.
Python 3.10+, Verilator, a C++ compiler, Make, and Yosys are required for the full
set. This run used Verilator 5.046 and Yosys 0.58 (157aabb58).

| Strict Verilator `--Wall` lint | Pass | Pass |
| Yosys synthesis and `check -assert` | Pass | Pass |

All 29 Python tests passed again. No arithmetic or transaction model changes were
needed. The simulator checks encoded words, decoded data, repaired words,
syndromes, correction/failure flags, and every MAC output. It also checks the raw
accumulator codeword before and after each edge and its stability off-edge.

Codec comparisons include 40 data patterns with no fault and all single/double
bit masks. The 8/24 run adds 2,000 arbitrary received words; the 4/8 run adds all
8,192 possible received codewords. These RTL expectations come from the Python
codec, which has separate known-word and distance-oracle checks.

Storage injections cover all single bits and double pairs at idle, acceptance,
and completion, over three states reached through normal MAC operations. There
is no accumulator preload. Tests include subsequent operation attempts, clear
recovery, busy clear/start, reset abort, and 3,000 seeded cycles mixing faults and
controls. Random streams can accumulate more than two corrupted bits; those cases
check agreement with the Python decoder, not a correction guarantee.

## Injection and harness checks

The C++ harness accesses `acc_codeword` through simulator visibility metadata,
XORs a mask while the clock is low, evaluates combinational logic, and checks
that the observed stored-word XOR equals the requested mask. It then checks
decoded readback and clocks the MAC. This models persistent stored-bit upsets
until overwritten or repaired. Check bits are included in the injection space.
The production RTL has no injection hardware.

The vector file starts with its expected record count. Negative controls confirm
that the runner returns failure for a wrong encoded-word expectation, cancellation
of an expected injection, and truncation of an otherwise valid file. These checks
run automatically with `make test-secded-rtl`.

## Evidence and limitations

Artifacts are under `build/secded_w8_a24/` and `build/secded_w4_a8/`:

- `vectors.json`: dimensions, seed, section counts, injection count, and vector hashes.
- `simulation.log`: observed cycle/codec/injection totals.
- `harness_checks.log`: negative-control results.
- `compile.log`, `synth.log`, `stat.json`, `netlist.v`, `netlist.json`: tool outputs.
- `provenance.json`: tool versions, Git state, and source/artifact hashes.

Simulation and synthesis targets refresh provenance after success. It inventories
present artifacts; it does not imply all artifacts were generated by one command.
Build outputs are ignored by Git and overwritten on reruns; preserve a complete
build directory when retaining a particular experiment.

The hardware decode/add/encode path has not been timed on the FPGA or ASIC. The
simulation retains the baseline cycle count but makes no clock-frequency claim.
This run uses Verilator's simulation semantics; XSim/four-state simulation,
post-synthesis equivalence, formal proof, and physical fault experiments are not
included. Accumulator data/check storage is the injection boundary. Operands,
arithmetic, encoder/decoder logic, control, clocks, and FPGA configuration bits
are not fault-injected here. Arbitrary larger fault patterns have no SECDED
guarantee. Target area/timing, board integration, and review remain open.
